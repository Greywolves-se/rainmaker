# ADR 0003: Live "Ask Navigator" questions through a small backend

- **Status:** Proposed. Needs approval by the owners (ongoing cost, company data to an external
  provider) and a senior review (security, login, CDK) before any code is written.
- **Date:** 19 Oct 2026
- **Decision log:** B36 (`apps/mission-control/data/mission-control/decisions.yaml`)
- **Issue:** #117. Builds on ADR 0002 (#115, AI text generated by the collector).

## Context

ADR 0001 says Mission Control V1 has no backend: the collector writes a snapshot and a static app
shows it. ADR 0002 adds AI text that the collector generates in advance (#115, #116). "Ask
Navigator" answers free-text questions about the page **live**, which a static app cannot do: the
OpenAI key must never reach the browser. This ADR adds the smallest backend that makes it possible,
and keeps everything else as in ADR 0001.

## Decision

**Where it runs**
- One **AWS Lambda** in Java 21, plain Java without Spring Boot, defined in CDK.
- Reached only through the existing load balancer, on the path `/api/navigator/*`, behind the same
  @graywolf.se Google login rule as the dashboard. **No Lambda Function URL**, because it would
  skip the login.
- The load balancer and its login must be in CDK first (#85), so the new listener rule is not
  added by hand to a hand-made load balancer.
- The Lambda **verifies the signature** of the `x-amzn-oidc-data` header the load balancer sends,
  and does not trust the header alone. The verified user is used for the per-person limit.

**API (contract-tested, owned by #117; the web box is connected in #116)**
- `POST /api/navigator/ask` with `{project, page, question, language}`.
- `200 {answer, model, generatedAt}`. The answer is plain text, labelled as AI in the web app.
- `400` question empty or too long; `401` not logged in; `429` limit reached; `503` switched off.

**Limits and cost**
- At most **10 questions per person per hour** and **200 per day for the whole team**.
- At most **500 characters** per question, and a `max_tokens` limit on the answer.
- Counters in a small **DynamoDB table with automatic expiry (TTL)**, so the limit holds across
  Lambda instances. It stores a hash of the user and a count, never the question.
- A **separate OpenAI project** with its own key and monthly spending limit, in Secrets Manager
  (for example `mission-control/openai-api-key-navigator`), read by the Lambda's own role. If live
  questions use up their budget, the summaries from #115 keep working, and each key can be revoked
  on its own.

**Kill switch**
- An SSM parameter (for example `/mission-control/navigator/ask-enabled`), created in CDK. The
  Lambda reads it with about one minute of caching; turning it off makes every question answer
  `503`, and the web app shows "not available right now".
- Backups: the OpenAI spending limit, then revoking the key.

**Data**
- Only the current page's data from the snapshot is sent, with the same anonymisation as #115:
  every person name and login is replaced with "Person A", "Person B" …, also in the question
  ("what is Kim working on?"), and mapped back in the answer.
- The anonymisation is one shared Java module (built in #115), used by both the collector and the
  Lambda, so there is one implementation, not two.
- Questions and answers are **not stored**. Logs never contain question or answer text (CLAUDE.md:
  no free text from users in logs), only counts, status and the correlation id.

**Model and language**
- The model follows ADR 0002, so there is one model decision, not two.
- The answer is in the language the reader has chosen (Swedish or English), sent with the question.

**Security**
- A fixed system prompt says the page data and the question are information, not instructions, and
  that answers may use only the given data (prompt-injection guard, as in #115).
- Answers are shown as plain text only, never HTML or Markdown links (#116).

## Consequences

- **ADR 0001 no longer fully holds:** Mission Control gets one backend function. The dashboard
  itself stays a snapshot plus a static app; only "Ask Navigator" calls the backend.
- **New AWS resources:** a Lambda, a listener rule, a DynamoDB table, an SSM parameter and a secret,
  all in CDK, with smallest sizes (CLAUDE.md).
- **Ongoing cost:** OpenAI per question (capped by the limits and the separate spending limit), plus
  small AWS costs.
- **Known limit:** a name that appears only in free text, and not in any person field of the
  snapshot, cannot be found and is sent as written. The same limit as in #115.
- **Cold start:** the first question after a pause takes a few seconds longer. The OpenAI answer
  itself takes several seconds, so this matters little. SnapStart can reduce it if it is available
  in `eu-north-1`; check before relying on it.

## Before it is switched on

- This ADR and ADR 0002 are approved by the owners.
- #85: the load balancer and the @graywolf.se login are in CDK and verified (a non-graywolf.se
  Google account is refused).
- #115: the shared anonymisation module exists.
- The separate OpenAI key and its spending limit exist.

## Alternatives considered

- **Lambda in Node/TypeScript:** faster cold start, but the anonymisation would exist twice in two
  languages and drift apart, and names reaching OpenAI is the main risk.
- **Lambda Function URL:** simpler, but skips the login.
- **The same OpenAI key as #115:** simpler, but spam on live questions could stop the summaries.
- **No live questions:** keep only the pre-generated text from #115. Still possible: #117 is
  `prio: could`, and the team may wait until #115 and #116 have shown that the AI text is useful.
